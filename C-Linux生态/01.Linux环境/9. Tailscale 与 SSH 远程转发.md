# 1. Tailscale 与 SSH 远程转发

两台机器不在同一局域网、也不想把 22 端口映射到公网时，用 **同一条 Tailscale 虚拟网 + SSH** 做远控、拷文件，以及按需把对端某个端口映到本机。密钥登录基础见 [[C-Linux生态/01.Linux环境/1. 常用指令|SSH 免密登录]]。同局域网共享工具链目录用 [[C-Linux生态/01.Linux环境/8. NFS 网络文件系统|NFS]]，不要和本方案混为一谈。

## 【核心精简提纲】

### 记忆主干

**Tailscale 只给虚拟 IP（`100.x`）**，不会自动映射整机端口。真正干活的是 **SSH**：登录、`scp`/`sftp`、以及 `ssh -L` 本地转发。USB 设备（ADB / 串口）仍在被控机上跑，主控只 SSH 过去代跑。

### 核心要点清单

- 两边必须登录 **同一个** Tailscale 账号（同一 tailnet）
- PC1 能建 TUN：直接 `ssh USER2@PC2_TS_IP`；无 root / 无 TUN：用户态 `--tun=userspace-networking` + 本机 SOCKS5 + `ProxyCommand`
- Windows 管理员公钥写 `C:\ProgramData\ssh\administrators_authorized_keys`，**不是** `C:\Users\<管理员>\.ssh\authorized_keys`
- 端口映射 = 挂着的 SSH 会话 + `-L 127.0.0.1:PORT1:127.0.0.1:PORT2`；会话断则映射断
- 用户态必须装 **OpenBSD netcat**（`nc -X`）；GNU netcat 没有 `-X`
- 不要在路由器上暴露 22 / 41641；`-L` 与 SOCKS5 都只绑 `127.0.0.1`

### 关键结论 / 流程

```plain
定角色（PC1 主控 / PC2 被控）
  → 两边装 Tailscale 并同一账号登录
  → tailscale ping 通
  → PC2 开 sshd，写入正确 authorized_keys
  → PC1 ssh 登录（用户态加 ProxyCommand）
  → 需要浏览器/本机客户端时再挂 ssh -L
```

## 【完整拓展详情】

## 1.1 目标与分层

```plain
PC1 主控（你坐的这头）
    │  Tailscale 虚拟网  100.x ↔ 100.y
    ▼
PC2 被控（对面那台）
    ├── OpenSSH Server
    ├── 文件、终端、本机服务
    └── 若有 USB 设备（手机、开发板、串口）：ADB / 串口工具仍跑在 PC2 上
```

| 你想做的事 | 用哪一层 |
|------------|----------|
| 远程敲命令 | SSH 登录 PC2 |
| 拷文件 | 同一条 SSH 上的 `scp` / `sftp` |
| 在 PC1 浏览器打开 PC2 上的 Web | SSH `-L` 本地转发 |
| PC2 插着 USB 设备 | **在 PC2 上跑** adb / 串口工具，PC1 只 SSH 过去代跑 |

不要：把 PC2 的 22 做路由器 / UU 端口映射到公网。

## 1.2 角色与准备

先定名字，后文按此替换：

| 符号 | 含义 | 填写提示 |
|------|------|----------|
| PC1 | 主控 | 家里 Linux / 办公室笔记本 |
| PC2 | 被控 | 插着设备的 Windows 或另一台 Linux |
| `USER1` | PC1 登录用户 | |
| `USER2` | PC2 SSH 用户 | Windows 上常用本地管理员账号 |
| `TS_ACCOUNT` | Tailscale 账号 | **两边必须同一个**（GitHub / Google / 邮箱均可） |
| `PC2_TS_IP` | PC2 的 Tailscale IPv4 | 登录后 `tailscale ip -4`，形如 `100.x.x.x` |

硬件与网络：

- 两边都能上网（各自 NAT 即可）
- PC1 已有或即将生成 SSH 密钥（`ed25519` 优先）
- PC2 能安装软件（Windows 需要一次管理员 PowerShell）
- 可选：PC1 若不能装内核 TUN（无 root、容器、权限受限），走下文「用户态 Tailscale」

系统组合都支持：Linux↔Windows、Linux↔Linux、Windows↔Windows。差别只在 **PC2 的 sshd 怎么装、公钥写哪**，以及 **PC1 有没有 TUN**。

## 1.3 选择 Tailscale 运行方式

| PC1 情况 | 选法 | SSH 怎么连 |
|----------|------|------------|
| 能装官方客户端（Windows；Linux 有 root） | **内核 / 系统服务** | `ssh USER2@PC2_TS_IP` 直接连 |
| 无 root、不能建 `tun` | **用户态** `--tun=userspace-networking` | 必须经本机 SOCKS5：`ProxyCommand` + `nc -X 5` |

PC2 一般装官方客户端即可（Windows 尤其如此）。用户态通常只出现在「受限的 Linux 主控」上。

两边都是官方客户端时最简单，**不必** SOCKS5。下面两套安装都写全，按 PC1 选一节做。

## 1.4 安装 Tailscale

### Windows（PC1 或 PC2）

1. 打开 [https://tailscale.com/download](https://tailscale.com/download) 安装，或管理员 PowerShell：

```powershell
$msi = Join-Path $env:TEMP 'tailscale-setup.msi'
Invoke-WebRequest -Uri 'https://pkgs.tailscale.com/stable/tailscale-setup-latest-amd64.msi' -OutFile $msi
Start-Process msiexec.exe -Wait -ArgumentList "/i `"$msi`" /qn"
```

2. 托盘图标登录，账号必须是 `TS_ACCOUNT`
3. 管理员 PowerShell 确认：

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' status
& 'C:\Program Files\Tailscale\tailscale.exe' ip -4
```

记下这台的 `100.x`。Windows 防火墙对 Tailscale 网卡放行即可，不必另开公网 22。

建议 `--accept-dns=false`（避免公司 DNS 被 MagicDNS 搅乱）：

```powershell
& 'C:\Program Files\Tailscale\tailscale.exe' up --accept-dns=false
```

### Linux 官方（有 root，PC1 或 PC2）

按官网当前脚本（发行版会变，以官网为准）：

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --accept-dns=false
sudo tailscale status
sudo tailscale ip -4
```

浏览器打开打印出的登录链接，用 **同一个** `TS_ACCOUNT`。

### Linux 用户态（无 root / 无 TUN）

适用于：共享服务器、不能 `sudo`、不能加载 TUN。思路：静态二进制 + 用户 systemd + 本机 SOCKS5。

**（1）下载官方静态包**

到 [https://pkgs.tailscale.com/stable/#static](https://pkgs.tailscale.com/stable/#static) 选 linux amd64 / arm64 的 `.tgz`。例如：

```bash
mkdir -p "$HOME/opt/tailscale" "$HOME/bin"
cd /tmp
# 把 URL 换成页面上的当前版本
curl -L -o tailscale.tgz 'https://pkgs.tailscale.com/stable/tailscale_1.xx.x_amd64.tgz'
tar -tzf tailscale.tgz   # 看目录名
tar -xzf tailscale.tgz
cp tailscale_*/tailscale tailscale_*/tailscaled "$HOME/opt/tailscale/"
chmod +x "$HOME/opt/tailscale/tailscale" "$HOME/opt/tailscale/tailscaled"
```

**（2）命令包装（指定 socket，避免和系统 tailscale 打架）**

```bash
cat > "$HOME/bin/tailscale" << EOF
#!/usr/bin/env bash
exec "$HOME/opt/tailscale/tailscale" --socket="$HOME/opt/tailscale/tailscaled.sock" "\$@"
EOF
chmod +x "$HOME/bin/tailscale"
```

保证 `export PATH="$HOME/bin:$PATH"` 写在 `~/.bashrc`。

**（3）用户 systemd**

```bash
mkdir -p "$HOME/.config/systemd/user"
cat > "$HOME/.config/systemd/user/tailscaled.service" << EOF
[Unit]
Description=Tailscale userspace daemon
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=$HOME/opt/tailscale/tailscaled --tun=userspace-networking --socks5-server=localhost:1055 --outbound-http-proxy-listen=localhost:1055 --state=$HOME/opt/tailscale/tailscaled.state --socket=$HOME/opt/tailscale/tailscaled.sock
Restart=always
RestartSec=3

[Install]
WantedBy=default.target
EOF

systemctl --user daemon-reload
systemctl --user enable --now tailscaled.service
loginctl enable-linger "$USER"   # 没登录也保持用户服务（若策略允许）
```

SOCKS5 / HTTP 代理都在 **`127.0.0.1:1055`**，只给本机用，不要改成 `0.0.0.0`。

**（4）登录**

```bash
tailscale login          # 或 tailscale up --accept-dns=false
tailscale status
tailscale ip -4
```

浏览器打开链接，仍用同一个 `TS_ACCOUNT`。

**（5）本机依赖**

用户态 SSH 必须走 SOCKS5，需要 **OpenBSD netcat**：

```bash
# Debian / Ubuntu
sudo apt install netcat-openbsd
nc -h 2>&1 | head -1    # 应能看到 OpenBSD
```

传统 GNU / `netcat-traditional` **没有** `-X`，会直接失败。

**验收用户态：**

```bash
ss -ltn | grep 1055          # 127.0.0.1:1055 在听
tailscale ping "$PC2_TS_IP"  # 能通即可；本机普通 ping 100.x 往往会失败，这是正常的
```

## 1.5 两边进同一张网

在 **PC1 和 PC2** 都执行：

```bash
tailscale status
```

期望：

- 自己是 `online`（不是 Logged out / offline）
- 能看到对面那台，主机名或 `100.x`
- `tailscale ping <对面>` 有回复。通时多为 **direct**；偶发 **relay** 也能用，只是慢、易抖

Logged out：重新 `tailscale login` / `tailscale up`。  
只看见自己：确认是同一个账号、没有开错 tailnet、邀请是否还在待批准。

到这一步，**转发还没开始**，只是虚拟网通了。

## 1.6 PC2 打开 SSH 服务

### PC2 是 Linux

```bash
sudo apt install openssh-server   # 或对应发行版
sudo systemctl enable --now ssh
```

把 **PC1 的公钥** 追加到 PC2 的 `~USER2/.ssh/authorized_keys`。密钥生成与分发见 [[C-Linux生态/01.Linux环境/1. 常用指令|SSH 免密登录]]。

PC1 若还没有钥匙：

```bash
ssh-keygen -t ed25519 -C 'pc1-to-pc2'
cat ~/.ssh/id_ed25519.pub
```

### PC2 是 Windows

用 **管理员 PowerShell**：

```powershell
# 安装并启动 OpenSSH Server
$cap = Get-WindowsCapability -Online | Where-Object { $_.Name -like 'OpenSSH.Server*' }
if ($cap.State -ne 'Installed') {
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
}
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
if (-not (Get-NetFirewallRule -Name sshd -ErrorAction SilentlyContinue)) {
  New-NetFirewallRule -Name sshd -DisplayName 'OpenSSH Server (sshd)' `
    -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22 | Out-Null
}
```

**管理员账号的公钥位置（必读）：**

Windows OpenSSH **不会读** `C:\Users\<管理员>\.ssh\authorized_keys`。

必须写：

```plain
C:\ProgramData\ssh\administrators_authorized_keys
```

权限：去掉继承，只给 `SYSTEM` 和 `Administrators` 完全控制。

```powershell
# 把下一行换成 PC1 的 id_ed25519.pub / id_rsa.pub 整行
$key = "ssh-ed25519 AAAA... comment"
$auth = "C:\ProgramData\ssh\administrators_authorized_keys"
New-Item -ItemType Directory -Force -Path "C:\ProgramData\ssh" | Out-Null
Add-Content -Path $auth -Value $key
icacls $auth /inheritance:r
icacls $auth /grant "SYSTEM:(F)" "Administrators:(F)"
Restart-Service sshd
```

普通非管理员用户才走 `C:\Users\<user>\.ssh\authorized_keys`。

本机防火墙放行 22 即可；公网路由器 **不要** 做 22 映射。Tailscale 走虚拟网卡进来。

对端默认 shell 是 **cmd.exe**：

- 远程命令不要用 bash 的 `;`、`&&` 当「Windows 语法」硬套（`cmd /c` 里 `&&` 可用，但 `|` 容易被吃掉）
- 要 PowerShell：`ssh ... powershell`
- 路径里的 `\` 经 Linux SSH 时容易被吃掉，远程路径尽量写 `/`，例如 `C:/Users/USER2/file`

## 1.7 PC1 连上 PC2

### PC1 是官方 Tailscale（有 TUN）

```bash
ssh USER2@PC2_TS_IP
# 或 MagicDNS（若已开）
ssh USER2@pc2主机名
```

第一次会问 host key，确认指纹后写入 `known_hosts`。

### PC1 是用户态（必须 SOCKS5）

```bash
ssh -o ProxyCommand='nc -X 5 -x 127.0.0.1:1055 %h %p' \
    -o StrictHostKeyChecking=accept-new \
    USER2@PC2_TS_IP
```

包装脚本，例如 `~/bin/ssh-peer`：

```bash
#!/usr/bin/env bash
# 经本机用户态 Tailscale SOCKS5 访问对端
set -euo pipefail
if [ $# -lt 1 ]; then
  echo "用法: ssh-peer [user@]host [ssh-args...]" >&2
  exit 1
fi
target=$1
shift
exec ssh \
  -o ProxyCommand='nc -X 5 -x 127.0.0.1:1055 %h %p' \
  -o StrictHostKeyChecking=accept-new \
  "$target" "$@"
```

```bash
chmod +x ~/bin/ssh-peer
ssh-peer USER2@PC2_TS_IP
ssh-peer USER2@PC2_TS_IP powershell    # Windows 上进 PowerShell
```

`scp` 同样要带 `ProxyCommand`：

```bash
scp -o ProxyCommand='nc -X 5 -x 127.0.0.1:1055 %h %p' \
    ./local.bin USER2@PC2_TS_IP:C:/Users/USER2/local.bin
```

### 免密与超时

```plain
# ~/.ssh/config 片段（官方 TUN 版）
Host pc2
    HostName PC2_TS_IP
    User USER2
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    ServerAliveCountMax 6

# 用户态版：加上
#   ProxyCommand nc -X 5 -x 127.0.0.1:1055 %h %p
```

登录成功后，控制面就通了。

## 1.8 按需做端口转发（这才是映射）

只在你需要「PC1 本机访问 PC2 上某个端口」时做。SSH 会话必须一直挂着。

### 本地转发：PC1 看 PC2 的服务

PC2 上已有服务听在 `127.0.0.1:PORT2`（或 `0.0.0.0:PORT2`）。

```bash
ssh -o ExitOnForwardFailure=yes \
    -o ServerAliveInterval=30 \
    -L 127.0.0.1:PORT1:127.0.0.1:PORT2 \
    USER2@PC2_TS_IP
```

用户态 PC1 记得加 `ProxyCommand`。

之后 PC1 浏览器打开 `http://127.0.0.1:PORT1`，流量是：

```plain
PC1:PORT1  --SSH 加密-->  PC2 回环 PORT2
```

Tailscale 外网看不到 `PORT1`（绑的是 `127.0.0.1`）。

### 转发要穿过「PC2 再转一层」（USB 设备上的 HTTP）

典型：PC2 USB 挂了一块开发板，板子 HTTP 在 `:8999`。PC2 先做 adb 转发，再 SSH `-L`：

```plain
PC1 127.0.0.1:18999
    -- SSH -L -->  PC2 127.0.0.1:18999
                     -- adb forward tcp:18999 tcp:8999 -->  设备 :8999
```

在 **PC2**（Windows 示例）：

```plain
adb forward tcp:18999 tcp:8999
```

在 **PC1** 挂上 `-L 127.0.0.1:18999:127.0.0.1:18999`，并让远端会话别退出，例如：

```bash
ssh-peer -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18999:127.0.0.1:18999 \
  USER2@PC2_TS_IP \
  cmd /c "adb forward tcp:18999 tcp:8999 && ping -n 86400 127.0.0.1"
```

要点：

- 空闲 SSH 被 Windows OpenSSH 掐掉时，**这条会话拉起的 adb forward 也会没**
- 所以用 `ServerAliveInterval` + 远端挂长命令保活
- ADB 不需要「映射整台 PC」；USB 永远在 PC2

### 反向转发

PC2 要访问 PC1 本机端口时用 `-R`。默认场景用不到，先不要开。

## 1.9 安全与边界

- Tailscale 账号开启 **2FA**；不要把 auth key 写进仓库
- SOCKS5 只绑 `127.0.0.1`
- `-L` 也只绑 `127.0.0.1`，除非你明确要给同局域网别人用
- 不在路由器上暴露 22 / 41641
- 换机、重装：重新 `tailscale up` + 重写 `authorized_keys` / `administrators_authorized_keys`
- 用户态 `tailscaled.state` 当密钥一样保管

本方案是 **终端 + 文件 + 指定端口**。若要看 PC2 的完整桌面，用 Tailscale IP 打 Windows 自带 RDP / 第三方远控即可，**不必**再做一层 22 公网映射。RDP 默认 3389，同样建议只在 Tailscale 网内放行，不要对公网开放。

## 1.10 排错

| 现象 | 先查 |
|------|------|
| `tailscale status` Logged out | 该机重新 login；链接要在浏览器里点完 |
| `offline` / 只有 relay | 两边都在线？公司网是否拦 UDP？先接受 relay，再查防火墙 |
| `ssh: connect to host 100.x timed out` | PC1 若是用户态，是否忘了 `ProxyCommand`？普通 `ping 100.x` 失败是预期 |
| `nc: invalid option -- X` | 安装 `netcat-openbsd` |
| `Permission denied (publickey)` | Windows 管理员是否写了 `administrators_authorized_keys`？权限是否只剩 SYSTEM+Administrators？ |
| 能 SSH、浏览器打不开转发端口 | SSH 会话是否还在？`-L` 是否 `ExitOnForwardFailure`？PC2 服务是否只听了别的网卡？ |
| 转发过一阵自己断 | 加 `ServerAliveInterval=30`；Windows 上不要只开一个空闲 ssh |
| 远程命令怪、管道没了 | 对端是 cmd；拆开执行，或显式 `powershell -NoProfile -Command ...` |
| 用户态与系统 tailscale 抢 socket | 包装脚本必须带 `--socket=.../tailscaled.sock` |

## 1.11 从零勾选清单

1. 选定 PC1 / PC2 / `TS_ACCOUNT` / `USER2`
2. PC1 生成 SSH 密钥，保存好私钥
3. 两边安装 Tailscale（PC1 按有无 TUN 选官方或用户态）
4. 两边用 **同一账号** 登录，`tailscale ping` 成功
5. PC2 安装并启动 sshd
6. 公钥写入正确位置（Windows 管理员走 `administrators_authorized_keys`）
7. PC1 `ssh`（用户态加 SOCKS5）登录成功
8. `scp` 一个小文件验证
9. （可选）一条 `-L`，本机访问 `127.0.0.1:PORT1`
10. （可选）USB 设备：PC2 上 adb/串口正常，PC1 只 SSH 代跑
11. 转发会话加保活，确认隔夜或锁屏后是否还在

到第 7 步，方案已经可用。8–11 按需求加。

## 1.12 最小命令速查

```bash
# 状态
tailscale status
tailscale ping PC2_TS_IP

# 登录（官方 TUN）
ssh USER2@PC2_TS_IP

# 登录（用户态）
ssh-peer USER2@PC2_TS_IP

# 拷文件（用户态）
scp -o ProxyCommand='nc -X 5 -x 127.0.0.1:1055 %h %p' \
    ./a.bin USER2@PC2_TS_IP:C:/Users/USER2/a.bin

# 把 PC2 的 8999 映到 PC1 的 18999
ssh-peer -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -L 127.0.0.1:18999:127.0.0.1:8999 USER2@PC2_TS_IP
```

把文中的 `PC2_TS_IP` / `USER2` / `TS_ACCOUNT` 换成实际值，从 §1.4 做到 §1.7 即可在新环境复刻整套转发。
