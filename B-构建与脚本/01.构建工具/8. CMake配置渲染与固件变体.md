# 1. CMake 配置渲染与固件变体

把版本号和功能开关留在 CMake，用一份清单生成宏、枚举和调用，再用 C++ 类型安全接口包一层。改固件变体不改算法源码。入门命令见 [[B-构建与脚本/01.构建工具/3. CMake入门与实践|CMake 入门]]，目标属性见 [[B-构建与脚本/01.构建工具/4. CMake进阶与复杂项目|CMake 进阶]]。

## 【核心精简提纲】

### 记忆主干

**一份 `ALGO_FEATURE_SPECS` → 拆字段、按类攒进变量 → 写出 `config.h` / `feature.gen.hpp` / `pipeline_init.inc` → `SemVer` 与 `Version` 对外查询。**

配置期决定版本号、功能开关、平台和编译器。每次编译才刷新 git 短哈希和构建时间。业务代码只写初始化函数体和头文件；调用行由清单生成。

### 核心要点清单

- 版本号来自 `project(... VERSION x.y.z)`，CMake 自动拆出 `PROJECT_VERSION` / `_MAJOR` / `_MINOR` / `_PATCH`
- 功能清单每行五段：`id|说明|默认|初始化函数|日志名`。`foreach` 按 `|` 拆开，再追加到四类字符串
- 打开的功能写成 `#define`，放进 `config.h.in` 的 `@ALGO_FEATURE_DEFINES@`。关掉的功能连这行都没有
- 枚举、`featureName`、`featureEnabled` 写入 `feature.gen.hpp`；流水线调用写入 `pipeline_init.inc`
- 平台和编译器 ID 在 configure 时写入 `config.h`。git 与时间戳由 `cmake/write_build_stamp.cmake` 在每次编译时重写
- 比较用 `SemVer` 值。诊断字符串用 `formatInfo(dst, dstLen)` 写入调用方缓冲区
- `featureCount()` 循环调用 `hasFeature()`，不要再手写一套平行的 `#ifdef`
- 关掉的模块连 `[skip]` 字符串也不进库。只有 `ALGO_DIAGNOSTIC_INIT` 打开时才打印跳过日志
- `ALGO_DEMO_REQUIRE_EKF` 只定义给演示程序。库本身允许没有 EKF
- `base` 预设不写死编译器。MinGW 用 `full-mingw` / `minimal-mingw` / `debug-mingw`
- 自己的函数：头文件和函数体放在手写 `.cpp` 里，并用同一个功能宏包住。生成器只发出调用
- MCU 上可用 `SemVer`、`hasFeature` 和宏裁剪。`formatInfo` / `printf` 会拉入格式化库，资源紧时不要放进周期任务

### 分层

| 层 | 落点 | 职责 |
|----|------|------|
| 配置 | `CMakeLists.txt` / `CMakePresets.json` | 版本、清单、开关、数值、平台 |
| 渲染 | `config.h`、`feature.gen.hpp`、`pipeline_init.inc` | 变量变成宏、枚举和调用 |
| 构建戳 | `build_stamp.h` | 每次编译刷新 git 与时间 |
| 领域 | `algo::SemVer`、`algo::Version` | 比较、兼容性、功能查询 |
| 使用 | 各模块 `.cpp` | 宏包住头文件和函数体 |

## 【完整拓展详情】

## 1.1 为什么要分层

MCU 算法库常要同一套源码打出多份固件：全功能、ROM 受限精简版、带调试模块的版本。版本号和功能开关若散落在手写头文件里，改一个变体就要改源码，清单也会在枚举、查询和初始化之间漂移。

分工是固定的：

- **编译期裁剪**靠宏。未启用模块的函数和头文件不要编进镜像。
- **运行时查询**走类型安全 API。调用点用枚举，不散落字符串比较。
- **调用顺序**由清单生成。每个模块的真实逻辑仍手写，因为参数和头文件各不相同。

`hasFeature()` 做成 `constexpr` 后，未启用分支在优化下可以被删掉。

## 1.2 版本号从哪里来

版本号写在 `project()`，不在模板里手写：

```cmake
cmake_minimum_required(VERSION 3.15)
project(algo_lib VERSION 2.1.0 LANGUAGES CXX)
```

| 变量 | 示例 |
|------|------|
| `PROJECT_VERSION` | `2.1.0` |
| `PROJECT_VERSION_MAJOR` | `2` |
| `PROJECT_VERSION_MINOR` | `1` |
| `PROJECT_VERSION_PATCH` | `0` |

改版本只改这一处，然后重新 configure。兼容规则放在 `SemVer::isCompatibleWith`：主版本相同，且次版本不低于要求。补丁号不参与兼容判断。规则说明见 [[A-编程语言/02.C++/6. C++ API设计|API 设计]]。

## 1.3 一份清单生成三份文件

清单是唯一来源：

```cmake
set(ALGO_FEATURE_SPECS
    "IMU_CALIBRATION|IMU calibration algorithm|ON|initImuCalibration|IMU calibration"
    "MAG_COMPENSATION|Magnetometer compensation|ON|initMagCompensation|Mag compensation"
    "EKF_FUSION|EKF fusion algorithm|ON|initEkfFusion|EKF fusion"
    "AHRS_SOLVER|AHRS heading solver|OFF|initAhrsSolver|AHRS solver"
)
```

`foreach` 对每一行做四件事：

1. `string(REPLACE "|" ";" ...)` 拆成 id、说明、默认开关、初始化函数、日志名。字段数不是 5 就 `FATAL_ERROR`。
2. `option(ALGO_FEATURE_${id} ...)` 注册开关。命令行、Preset 和缓存里的值优先于默认值。
3. 开关为真时，向 `ALGO_FEATURE_DEFINES` 追加 `#define ALGO_FEATURE_<id>`。
4. 将其余文本追加到枚举、名称分支、启用分支、流水线调用四个变量。

循环结束后：

| 变量 | 生成文件 | 谁包含 |
|------|----------|--------|
| 枚举 + 两个 switch | `generated/algo/feature.gen.hpp` | `include/algo/feature.hpp` |
| 流水线调用 | `generated/algo/pipeline_init.inc` | `Pipeline::init()` |
| `#define` 列表 | 交给 `configure_file` 填进 `config.h` | 公共头 |

`feature.gen.hpp` 用 `string(CONFIGURE [[ ... ]])` 把变量填进模板，再 `file(WRITE)`。`[[ ]]` 字面量本身不展开 `${}`，由 `string(CONFIGURE)` 展开，避免引号被 CMake 提前吃掉。

生成的调用形状固定：

```cpp
#if defined(ALGO_FEATURE_IMU_CALIBRATION)
    initImuCalibration();
#elif defined(ALGO_DIAGNOSTIC_INIT)
    std::printf("  [skip] %s (not in this firmware)\n", "IMU calibration");
#endif
```

函数体不生成。名字必须和清单第四列一致，否则编译失败。这是故意的：漏写函数时构建直接报错。

`#cmakedefine` 仍可用在别的模板上，但功能开关不再逐条手写它。CMake 会扫描模板里的 `#cmakedefine`，这个关键字不要出现在注释中。

## 1.4 配置期头与每次编译的构建戳

`config.h.in` 只放重新配置前不会变的量。字符串宏在占位符外加引号，整数宏不加：

```cmake
#define ALGO_VERSION_MAJOR  @PROJECT_VERSION_MAJOR@
#define ALGO_VERSION_STRING "@PROJECT_VERSION@"
#define ALGO_TARGET_PLATFORM "@TARGET_PLATFORM@"
#define ALGO_COMPILER_ID     "@CMAKE_CXX_COMPILER_ID@"
@ALGO_FEATURE_DEFINES@
#define ALGO_MAX_SENSOR_CHANNELS @ALGO_MAX_SENSOR_CHANNELS@
#define ALGO_EKF_STATE_DIM       @ALGO_EKF_STATE_DIM@
```

```cmake
configure_file(
    "${CMAKE_CURRENT_SOURCE_DIR}/config.h.in"
    "${CMAKE_CURRENT_BINARY_DIR}/generated/algo/config.h"
    @ONLY
)
```

`@ONLY` 只替换 `@FOO@`。生成物在 `build/` 下，不提交。只 `cmake --build` 不会刷新这些宏。

平台在 configure 时用 `CMAKE_SYSTEM_PROCESSOR` 归成 `ARM32`、`ARM64` 或本机处理器名。`CMAKE_CXX_COMPILER_ID` 由 CMake 探测，GCC 为 `GNU`。宿主机编出来是本机名。要得到 ARM 固件，需要 [[C-Linux生态/03.Linux开发/2. 交叉编译优化选项|交叉编译 toolchain]]，让 `CMAKE_SYSTEM_PROCESSOR` 变成 `arm`。平台字符串只用于日志，不改变指令集。

git 短哈希和构建时间若在 configure 时用 `string(TIMESTAMP)` 写死，增量编译不会更新。当前做法是每次构建跑脚本：

```cmake
add_custom_target(algo_build_stamp ALL
    COMMAND ${CMAKE_COMMAND} -DGIT_EXECUTABLE=${ALGO_GIT_EXECUTABLE}
            -DSOURCE_DIR=${CMAKE_SOURCE_DIR}
            -DOUT_FILE=${_algo_stamp}
            -P "${_algo_stamp_script}"
    BYPRODUCTS "${_algo_stamp}"
    VERBATIM
)
add_dependencies(algo_lib algo_build_stamp)
set_source_files_properties(src/version.cpp PROPERTIES OBJECT_DEPENDS "${_algo_stamp}")
```

`cmake/write_build_stamp.cmake` 写 `build_stamp.h`。仓库不存在或 `rev-parse` 失败时哈希为 `unknown`，configure 不因此失败。configure 时先 `execute_process` 写一份，保证第一次编译能找到头。`OBJECT_DEPENDS` 只绑 `version.cpp`，时间戳变化时流水线不必重编。

要可复现构建时，时间戳应改读 `SOURCE_DATE_EPOCH`，没有该环境变量再回退到当前时间。

## 1.5 让编译器看见生成头

```cmake
add_library(algo_lib STATIC
    src/pipeline.cpp
    src/version.cpp
)
target_include_directories(algo_lib
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}/generated>
)
target_compile_features(algo_lib PUBLIC cxx_std_17)
```

`PUBLIC` 表示链接 `algo_lib` 的程序也能包含 `algo/config.h`。`BUILD_INTERFACE` 把路径限制在本仓库构建。可见性见 [[B-构建与脚本/01.构建工具/4. CMake进阶与复杂项目|CMake 进阶]]。

`include/algo/feature.hpp` 必须先包含 `algo/config.h`，再包含 `algo/feature.gen.hpp`。生成的 `featureEnabled()` 靠这些宏决定返回值；顺序反了，所有功能都会看起来是关的。

诊断宏和产品要求用 `PRIVATE`，不要写进公共头：

```cmake
if(ALGO_DIAGNOSTIC_INIT)
    target_compile_definitions(algo_lib PRIVATE ALGO_DIAGNOSTIC_INIT)
endif()
if(ALGO_DEMO_REQUIRE_EKF)
    target_compile_definitions(algo_demo PRIVATE ALGO_DEMO_REQUIRE_EKF)
endif()
```

数值参数仍是缓存字符串，Preset 可以改数字：

```cmake
set(ALGO_MAX_SENSOR_CHANNELS 8 CACHE STRING "Max sensor channels")
set(ALGO_EKF_STATE_DIM 15 CACHE STRING "EKF state vector dimension")
```

## 1.6 SemVer 与诊断字符串

版本比较是一个值，不是三个散落的整数参数：

```cpp
struct SemVer {
    uint8_t major{};
    uint8_t minor{};
    uint8_t patch{};

    static constexpr SemVer current() noexcept {
        return {
            static_cast<uint8_t>(ALGO_VERSION_MAJOR),
            static_cast<uint8_t>(ALGO_VERSION_MINOR),
            static_cast<uint8_t>(ALGO_VERSION_PATCH),
        };
    }

    constexpr int compare(SemVer other) const noexcept;
    constexpr bool isCompatibleWith(SemVer required) const noexcept;
};
```

`Version` 保留构建身份和功能查询。`featureCount()` 从 `hasFeature()` 推导，编译期折成常量。`FEATURE_COUNT` 是种类上限，`featureCount()` 是本固件打开的个数。

诊断字符串由调用方提供缓冲区。返回值与 `snprintf` 相同：不含结尾 NUL 的完整长度。`dstLen > 0` 时保证 NUL 结尾；长度大于等于缓冲区大小表示被截断。

```cpp
char info[192];
const std::size_t needed = algo::formatInfo(info, sizeof(info));
```

`formatInfo` 放在 `version.cpp`，公共头不再包含 `<cstdio>`。不要返回指向函数内 `static` 缓冲区的 `string_view`，下一次调用会覆盖上一次的结果。

git 与时间戳的访问函数返回指向构建戳字符串字面量的 `string_view`，生命周期是整个进程。

产品目标可以要求某个模块必须存在，这个断言放在该目标的源文件里，并用它自己的宏包住：

```cpp
#if defined(ALGO_DEMO_REQUIRE_EKF)
static_assert(algo::Version::hasFeature(algo::FeatureFlag::EKF_FUSION),
              "EKF fusion is required for this product target");
#endif
```

库本身不假设 EKF 一定打开。

## 1.7 调用自己的函数

生成器只生成调用。头文件写在手写的 `.cpp` 里，和函数体放在同一对功能宏下面：

```cpp
#ifdef ALGO_FEATURE_IMU_CALIBRATION
#include "imu/calibration.hpp"

void initImuCalibration() {
    imu::Calibration calib(ALGO_MAX_SENSOR_CHANNELS);
    calib.start();
}
#endif
```

宏未定义时，预处理会拿掉整段，对应头文件不会被打开。`pipeline_init.inc` 也只在宏打开时调用该函数。

模块一多，每个模块单独一个 `.cpp`。`pipeline.cpp` 里只留声明：

```cpp
#ifdef ALGO_FEATURE_IMU_CALIBRATION
void initImuCalibration();
#endif
```

每个模块的调用形状要一致，通常是 `void name()`，或都接收同一个上下文。参数各不相同时，保留这个外壳，在外壳里再调用真实接口。

## 1.8 Preset

隐藏的 `base` 放生成器、构建类型和按预设名分开的 `binaryDir`。具名预设只覆盖差异。`base` 不设置 `CMAKE_CXX_COMPILER`，这样 MSVC 与 MinGW 都能用同一套功能预设。本机 MinGW 再继承出 `*-mingw`，只追加 `g++`。

```bash
cmake --preset minimal-mingw
cmake --build --preset minimal-mingw
ctest --test-dir build/minimal-mingw --output-on-failure
```

`binaryDir` 使用 `${presetName}`，full 与 minimal 不会共用一个缓存。`buildPresets` 与 configure 预设同名后，`--build --preset` 才能找到目录。

| 项 | full | minimal | debug |
|----|------|---------|-------|
| 功能 | 四个都开 | IMU 与 EKF 开，MAG / AHRS 关 | 默认再打开 AHRS |
| 通道数 | 8 | 4 | 8 |
| 跳过日志 | 关 | 关 | `ALGO_DIAGNOSTIC_INIT=ON` |
| 演示程序要求 EKF | 开 | 关，因此可以把 EKF 也关掉 | 开 |

`minimal` 默认仍编译 EKF。要裁掉它，重新配置时加 `-DALGO_FEATURE_EKF_FUSION=OFF`。该项仍为 `ON` 且 `ALGO_DEMO_REQUIRE_EKF=ON` 时，演示程序会在编译期失败，库目标本身仍能编过。

## 1.9 在 MCU 上用哪些

`SemVer::current()`、`compare`、`isCompatibleWith`、`hasFeature` 和 `config.h` 宏可以放在 MCU 上。它们不分配内存，条件是编译期常量，关闭的分支可以被删掉。`std::string_view` 在 `arm-none-eabi-g++` 的 C++17 标准库里指向 Flash 中的字符串字面量。

工具链要换成交叉编译器，并打开 C++17。当前 `*-mingw` 预设编的是 PC 程序。

`formatInfo` 和流水线里的 `printf` 会链入 `snprintf`。资源紧的固件不要在周期任务里调用；只在开机打一行版本时，再接受这份 Flash 开销。只做版本和功能判断时，不要调用这两处。MCU 上的日志更适合 [[D-系统与架构/04.MCU嵌入式/1. mcu开发基础|vsnprintf 后自行送串口]]。

关掉宏之后，还要用 map 文件或 `size` 确认未引用段真的没进 ROM。链接侧见 [[B-构建与脚本/01.构建工具/7. 链接脚本（Linker Script）|链接脚本]]，并配合 `--gc-sections`。

## 1.10 还要手写的部分

- 初始化函数体和它的头文件。清单只保证调用形状一致。
- `|` 不能出现在说明文字里，否则字段拆分会错。
- 这套库没有 `install()` / `export()`。第二个工程要链接它时再补包配置。
- 演示里的模块体可以只是日志。换成真实算法后，裁剪规则不变：宏、头文件、函数体三者同时存在或同时消失。
