# 1. CMake 配置渲染与固件变体

把版本号、功能开关和数值参数留在 CMake，经模板渲染成 C 宏，再用 C++ 类型安全接口包一层。改固件变体不改算法源码。入门命令见 [[B-构建与脚本/01.构建工具/3. CMake入门与实践|CMake 入门]]，目标属性见 [[B-构建与脚本/01.构建工具/4. CMake进阶与复杂项目|CMake 进阶]]。

## 【核心精简提纲】

### 记忆主干

**CMake 变量 → `.in` 模板 → 生成 `config.h` 宏 → `Version` 封装 → 对外类型安全 API。**

配置层可被命令行、`CMakePresets.json`、CI 改写；渲染层只做替换；领域层把宏收成 `constexpr` 查询；业务层编译期用宏，运行时用类。

### 核心要点清单

- 版本号来自 `project(... VERSION x.y.z)`，CMake 自动拆出 `PROJECT_VERSION` / `_MAJOR` / `_MINOR` / `_PATCH`
- Git、时间戳、平台是普通 CMake 变量，模板里写成 `@VAR@`，由 `configure_file(... @ONLY)` 填进生成头
- 功能开关用 `option()` + `#cmakedefine`：开则 `#define`，关则 `/* #undef NAME */`
- 数值用 `set(... CACHE STRING ...)`，模板里 `@NAME@` 不加引号，生成整数宏
- 生成头放在 `build/`，用 `$<BUILD_INTERFACE:.../generated>` 暴露给依赖方
- 编译期决策用 `#if` / `static_assert`；运行时查询用 `Version::hasFeature()`
- 多份固件用 `CMakePresets.json` 的 `cacheVariables` 覆盖同一套源码
- `#cmakedefine` 写在注释里也会被处理，注释不要出现这个关键字

### 分层

| 层 | 落点 | 职责 |
|----|------|------|
| 配置 | `CMakeLists.txt` / `CMakePresets.json` | 版本、开关、数值、平台 |
| 渲染 | `config.h.in` → `build/.../config.h` | 变量变成 C 宏 |
| 领域 | `algo::Version` | 比较、兼容性、功能查询 |
| 使用 | 业务代码 | 宏做裁剪，类做查询 |

## 【完整拓展详情】

## 1.1 为什么要分层

MCU 算法库常要同一套源码打出多份固件：全功能、ROM 受限精简版、带调试模块的版本。若把版本号和 `#define FEATURE_xxx` 写死在手写头文件里，改一个变体就要改源码，CI 也无法只靠参数切换。

分工是固定的：

- **编译期裁剪**仍靠宏。未启用模块的函数不要编进镜像，这是宏不可替代的地方。
- **运行时查询**走类型安全 API。调用点不再散落 `#ifdef`，功能名用枚举而不是字符串。

`Version` 上的查询做成 `constexpr` 后，未启用分支在优化下可以被删掉，MCU 上这条路径没有运行时表查找。

## 1.2 版本号从哪里来

版本号不在模板里手写，写在 `project()`：

```cmake
cmake_minimum_required(VERSION 3.15)
project(algo_lib VERSION 2.1.0 LANGUAGES CXX)
```

CMake 据此生成：

| 变量 | 示例 |
|------|------|
| `PROJECT_VERSION` | `2.1.0` |
| `PROJECT_VERSION_MAJOR` | `2` |
| `PROJECT_VERSION_MINOR` | `1` |
| `PROJECT_VERSION_PATCH` | `0` |

改版本只改这一处，重新 configure 即可。语义上：主版本不同视为不兼容；同主版本且次版本不低于要求视为兼容。判断放在 `Version::isCompatibleWith`，规则说明见 [[A-编程语言/02.C++/6. C++ API设计|API 设计]]。

## 1.3 构建元数据从哪里来

Git 短哈希、构建时间、目标平台、编译器 ID 都是 configure 阶段算好的变量，不是编译器宏。

```cmake
find_package(Git QUIET)
if(GIT_FOUND)
    execute_process(
        COMMAND ${GIT_EXECUTABLE} rev-parse --short HEAD
        WORKING_DIRECTORY ${CMAKE_SOURCE_DIR}
        OUTPUT_VARIABLE GIT_COMMIT_HASH
        OUTPUT_STRIP_TRAILING_WHITESPACE
        RESULT_VARIABLE GIT_RESULT
        ERROR_QUIET
    )
    if(NOT GIT_RESULT EQUAL 0)
        set(GIT_COMMIT_HASH "unknown")
    endif()
else()
    set(GIT_COMMIT_HASH "unknown")
endif()

string(TIMESTAMP BUILD_TIMESTAMP "%Y-%m-%dT%H:%M:%S")

if(CMAKE_SYSTEM_PROCESSOR MATCHES "arm|ARM")
    set(TARGET_PLATFORM "ARM32")
elseif(CMAKE_SYSTEM_PROCESSOR MATCHES "aarch64|ARM64")
    set(TARGET_PLATFORM "ARM64")
else()
    set(TARGET_PLATFORM "${CMAKE_SYSTEM_PROCESSOR}")
endif()
```

`CMAKE_CXX_COMPILER_ID` 由 CMake 探测编译器后自带（GCC 为 `GNU`），不用 `set`。

目录还不是 Git 仓库、或 `rev-parse` 失败时，哈希保持 `unknown`，不要让 configure 失败。现场对固件时，有哈希就能对上某次提交；没有则至少还有版本号和时间戳。

## 1.4 模板与 configure_file

`config.h.in` 用 `@变量名@` 占位。字符串宏在占位符外加引号，整数宏不加：

```cmake
#define ALGO_VERSION_MAJOR  @PROJECT_VERSION_MAJOR@
#define ALGO_VERSION_STRING "@PROJECT_VERSION@"
#define ALGO_GIT_COMMIT      "@GIT_COMMIT_HASH@"
#define ALGO_BUILD_TIMESTAMP "@BUILD_TIMESTAMP@"
#define ALGO_TARGET_PLATFORM "@TARGET_PLATFORM@"
#define ALGO_COMPILER_ID     "@CMAKE_CXX_COMPILER_ID@"
```

渲染命令：

```cmake
configure_file(
    "${CMAKE_CURRENT_SOURCE_DIR}/config.h.in"
    "${CMAKE_CURRENT_BINARY_DIR}/generated/algo/config.h"
    @ONLY
)
```

`@ONLY` 只替换 `@FOO@`，不处理 `${FOO}`。生成物在 `build/` 下，不提交进源码树。configure 一次写一次；改 `project(VERSION)` 或 Preset 后必须重新 configure，只 `cmake --build` 不会刷新这些宏。

生成结果形态：

```c
#define ALGO_VERSION_MAJOR  2
#define ALGO_VERSION_STRING "2.1.0"
#define ALGO_GIT_COMMIT      "unknown"
#define ALGO_BUILD_TIMESTAMP "2026-09-22T15:47:32"
#define ALGO_TARGET_PLATFORM "AMD64"
#define ALGO_COMPILER_ID     "GNU"
```

宿主机上编出来平台是本机处理器名。要得到 ARM32 固件，需要 [[C-Linux生态/03.Linux开发/2. 交叉编译优化选项|交叉编译 toolchain]]，让 `CMAKE_SYSTEM_PROCESSOR` 变成 `arm`。只在 `else` 分支里写死 `"ARM32"` 不会改变实际指令集。

## 1.5 功能开关：option 与 cmakedefine

```cmake
option(ALGO_FEATURE_IMU_CALIBRATION  "IMU calibration algorithm" ON)
option(ALGO_FEATURE_MAG_COMPENSATION "Magnetometer compensation" ON)
option(ALGO_FEATURE_EKF_FUSION       "EKF fusion algorithm"      ON)
option(ALGO_FEATURE_AHRS_SOLVER      "AHRS heading solver"       OFF)
```

`option` 进入缓存，之后可被 `-D` 或 Preset 覆盖。模板侧：

```cmake
#cmakedefine ALGO_FEATURE_IMU_CALIBRATION
#cmakedefine ALGO_FEATURE_MAG_COMPENSATION
#cmakedefine ALGO_FEATURE_EKF_FUSION
#cmakedefine ALGO_FEATURE_AHRS_SOLVER
```

CMake 的规则：变量为真时该行变成 `#define NAME`；为假时变成 `/* #undef NAME */`。因此 `#ifdef ALGO_FEATURE_AHRS_SOLVER` 在精简固件里为假。

注释里不要写 `#cmakedefine`。CMake 按行扫描这个关键字，写在说明文字里会多生成一行残缺的 `/* #undef */`。

数值参数用缓存字符串，便于 Preset 改数字而不改类型系统：

```cmake
set(ALGO_MAX_SENSOR_CHANNELS 8 CACHE STRING "Max sensor channels")
set(ALGO_EKF_STATE_DIM 15 CACHE STRING "EKF state vector dimension")
```

```cmake
#define ALGO_MAX_SENSOR_CHANNELS @ALGO_MAX_SENSOR_CHANNELS@
#define ALGO_EKF_STATE_DIM       @ALGO_EKF_STATE_DIM@
```

三种写入方式对照：

| 头文件内容 | CMake 来源 | 模板写法 |
|------------|------------|----------|
| 版本号 | `project(VERSION)` 自动变量 | `@PROJECT_VERSION_MAJOR@` |
| Git / 时间 / 平台 / 编译器 | `execute_process`、`string(TIMESTAMP)`、`set`、内置变量 | `@GIT_COMMIT_HASH@` 等 |
| 功能开关 | `option()` | `#cmakedefine NAME` |
| 通道数、状态维 | `set(... CACHE STRING)` | `@NAME@` |

## 1.6 让编译器看见生成头

生成目录不是源码 `include/`，必须单独加进目标：

```cmake
add_library(algo_lib STATIC src/algo_core.cpp)
target_include_directories(algo_lib
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<BUILD_INTERFACE:${CMAKE_CURRENT_BINARY_DIR}/generated>
)
target_compile_features(algo_lib PUBLIC cxx_std_17)
```

`PUBLIC` 表示链接 `algo_lib` 的可执行文件也能 `#include "algo/config.h"`。`BUILD_INTERFACE` 把该路径限制在本仓库构建，不写进安装后的使用要求。可见性语义见 [[B-构建与脚本/01.构建工具/4. CMake进阶与复杂项目|CMake 进阶]]。

## 1.7 Version：宏外面的类型安全层

头文件只做薄封装，数据全部来自生成宏：

```cpp
static constexpr uint8_t major() noexcept {
    return static_cast<uint8_t>(ALGO_VERSION_MAJOR);
}

static constexpr bool hasFeature(FeatureFlag flag) noexcept {
    switch (flag) {
#ifdef ALGO_FEATURE_EKF_FUSION
        case FeatureFlag::EKF_FUSION:
            return true;
#endif
        default:
            return false;
    }
}

static constexpr bool isCompatibleWith(uint8_t reqMajor, uint8_t reqMinor = 0) noexcept {
    return major() == reqMajor && minor() >= reqMinor;
}
```

功能枚举与名称映射放在单独头里，供日志使用。`FEATURE_COUNT` 表示能力种类上限，`featureCount()` 表示本固件实际打开的个数，两者不要混用。

业务侧两种用法并存：

```cpp
#if ALGO_VERSION_MAJOR >= 2
#define USE_NEW_EKF_API 1
#endif

static_assert(algo::Version::hasFeature(algo::FeatureFlag::EKF_FUSION),
              "EKF fusion is required for this build!");

if (algo::Version::hasFeature(algo::FeatureFlag::IMU_CALIBRATION)) {
    imuCalibrationModule.init();
}
```

模块的实现函数本身再用 `#ifdef` 包住。这样精简固件里，对应 `.cpp` 中的函数体不会进入目标文件；运行时分支只负责打印「本固件未包含」。

诊断字符串（版本 + git + 平台 + 时间 + 功能计数）用 `snprintf` 填静态缓冲，在初始化时调用一次。它不是 `constexpr`。

## 1.8 Preset：一套源码，多份固件

`CMakePresets.json` 把变体收成可复现命令。隐藏的 `base` 放公共项，具名预设只覆盖差异：

```json
{
  "version": 3,
  "configurePresets": [
    {
      "name": "base",
      "hidden": true,
      "generator": "Ninja",
      "binaryDir": "${sourceDir}/build/${presetName}",
      "cacheVariables": { "CMAKE_BUILD_TYPE": "Release" }
    },
    {
      "name": "full",
      "inherits": "base",
      "cacheVariables": {
        "ALGO_FEATURE_IMU_CALIBRATION": "ON",
        "ALGO_FEATURE_MAG_COMPENSATION": "ON",
        "ALGO_FEATURE_EKF_FUSION": "ON",
        "ALGO_FEATURE_AHRS_SOLVER": "ON"
      }
    },
    {
      "name": "minimal",
      "inherits": "base",
      "cacheVariables": {
        "ALGO_FEATURE_IMU_CALIBRATION": "ON",
        "ALGO_FEATURE_MAG_COMPENSATION": "OFF",
        "ALGO_FEATURE_EKF_FUSION": "ON",
        "ALGO_FEATURE_AHRS_SOLVER": "OFF",
        "ALGO_MAX_SENSOR_CHANNELS": "4"
      }
    }
  ],
  "buildPresets": [
    { "name": "full", "configurePreset": "full" },
    { "name": "minimal", "configurePreset": "minimal" }
  ]
}
```

```bash
cmake --preset full && cmake --build --preset full
cmake --preset minimal && cmake --build --preset minimal
```

`binaryDir` 按预设名分开，避免 full 与 minimal 共用一个缓存、后一次 configure 覆盖前一次开关。`buildPresets` 与 `configurePresets` 同名后，`--build --preset` 才能找到对应构建目录。

期望对照：

| 项 | full | minimal |
|----|------|---------|
| 功能 | 四个都 `#define` | MAG / AHRS 为 `#undef` |
| 通道数 | 8 | 4 |
| 流水线 | 模块全部初始化 | 关闭项走跳过分支 |

## 1.9 边界

这套分层解决「配置进构建系统、宏负责裁剪、类负责查询」。下面几件事它还没有自动保证：

- **功能清单写了多处。** `option`、`#cmakedefine`、枚举、`hasFeature` 的 `switch` 要人工对齐。下一步是单一清单生成这几处，或让模块在编译期声明自己的版本依赖。
- **关掉开关不等于镜像变小。** 需要 map / `size` / 链接脚本的 `--gc-sections` 证明未引用目标真的没进 ROM。链接侧见 [[B-构建与脚本/01.构建工具/7. 链接脚本（Linker Script）|链接脚本]]。
- **`string(TIMESTAMP)` 使两次构建二进制不同。** 要可复现构建时，改读 `SOURCE_DATE_EPOCH`，没有该环境变量再回退到当前时间。
- **平台字符串不是工具链。** `TARGET_PLATFORM` 只用于日志。指令集、sysroot、浮点 ABI 由 toolchain 文件决定。
